# Гигиена секретов

Как только в работе появляется ключ, токен, пароль, файл доступа или личные данные клиентов
компании - сразу и простыми словами сказать человеку: где это будет лежать, куда может утечь
и что сделано, чтобы не утекло. Не ждать вопроса.

## Приём секретов
- Пароли, токены и коды не просить в чат: переписка хранится на сервере (`state.db`).
- Ключ кладётся в `.env` профиля мимо переписки: `hermes -p <профиль> config env set ИМЯ` в
  терминале сервера (или веб-панель Hermes, страница Keys). Токен Telegram-бота - через
  `hermes -p <профиль> gateway setup`.
- Ключи в `config.yaml` открытым текстом не хранить: только `${ИМЯ_ПЕРЕМЕННОЙ}`.

## Бэкап
- Бэкап (`scripts/git-backup.py`) кладёт в приватный GitHub только то, что не исключено `.gitignore`
  корня Hermes. Новый файл с секретом - ДО сохранения добавить в `.gitignore` и проверить
  `git check-ignore -v <путь>`.
- Скрипт бэкапа сам отменяет коммит, если в файле лежит живой ключ из `.env` любого профиля.
- Переписки (sqlite) по умолчанию в бэкап не идут (`BACKUP_DB_DUMPS=1` включает).
- `.gitignore` не чистит историю: закоммиченный секрет - сменить ключ, историю переписывать
  только с явного "да" владельца.

## Персональные данные клиентов компании
Паспорта, диагнозы, телефоны, адреса - в базу и заметки не писать, только обезличенно.
Файлы с такими данными - не пересылать наружу без прямой команды.
