# Сторож нагрузки сервера Hermes

Триггеры: "проверь процессы", вопрос про нагрузку, пришла тревога "Сервер Hermes".

## Что работает
- Скрипт `scripts/server_monitor.py` профиля (без ИИ, только стандартная библиотека):
  без флагов - замер и тревоги (пустой вывод = тишина); `--digest` - сводка за сутки; `--status` - цифры сейчас.
- Крон `server-monitor` (каждые 5 минут, без ИИ) и `server-digest-morning` (9:00). Включены только
  в одном профиле сервера - том, кто обслуживает сервер.
- Данные: `<профиль>/monitor/history.jsonl` (30 дней), `state.json` (антиспам: одна тревога раз в час).

## Пороги
Память 80/95%, процессор 85% два замера подряд, диск 80/92%, процессы, убитые из-за памяти,
не запущен шлюз Hermes. Процесс вне белого списка старше 60 минут - "лишний".
Шлюз подписок CLIProxyAPI проверяется только при `MONITOR_EXPECT_PROXY=1`.

## "Проверь процессы"
1. `python3 scripts/server_monitor.py --status` и `ps -u $(id -u) -o pid,ppid,etimes,times,rss,stat,args`.
2. По каждому лишнему процессу выяснить, кто запустил (ppid, фоновые процессы, кроны).
3. Показать таблицу: что это, сколько ест, что предлагаю (выключить или оставить) - и ЖДАТЬ согласия.
4. После согласия - `kill PID`, проверить, что исчез.
5. Штатный постоянный процесс - дописать подстроку в `WHITELIST` скрипта.

## Правило для самого помощника
Фоновые процессы, которые запускаю сам (браузер, серверы, долгие скрипты), - выключать по завершении задачи.
