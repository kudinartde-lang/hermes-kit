# Шлюз подписок (pool)

Claude, ChatGPT, Kimi - одна или несколько подписок - в одном окне. В приложении в одном списке
модели всех подписок, в любом чате можно выбрать любую. Кончился лимит у одного аккаунта - шлюз
сам берёт следующий аккаунт той же семьи.

## Как устроено
На сервере работает программа-посредник CLIProxyAPI (только внутри сервера, порт 8317, наружу не открыт).
В неё один раз входят своими подписками, как на обычном сайте. Помощники Hermes ходят в неё как в
одного поставщика `pool`.

## Честно предупредить владельца
- Подписки через сторонний шлюз могут нарушать правила OpenAI и Anthropic. Риск ограничения аккаунта
  небольшой, но не нулевой. Лимиты общие с обычным ChatGPT и Claude этого аккаунта.
- Вход в Claude живёт ~10 дней без использования, потом нужен повторный вход (сторож шлюза предупредит).

## Установка (один раз на сервер, 15-20 минут)
    cd ~/hermes-kit
    tools/pool-install.sh                  # сборка из исходника одобренной версии и запуск
    tools/pool-login.sh chatgpt            # человек рядом: ссылка + код
    tools/pool-login.sh claude             # человек рядом: ссылка, потом адрес из браузера
    tools/pool-install.sh --check          # шлюз жив, какие модели видит
    tools/features.sh --id anna --on pool  # подключить помощника (каждого, кому нужно)

После --on pool у помощника: основная модель - через шлюз, `/model strong | main | light`
и `/model pool-<модель>` для любой модели шлюза. Роли выбираются сами по тому, что есть;
задать явно: `POOL_STRONG=... POOL_MAIN=... POOL_LIGHT=... tools/features.sh --id anna --on pool`.
Не менять основную модель: `POOL_MAKE_DEFAULT=0`.

## Подписка по ключу (Kimi и подобные)
Не OAuth, а обычный ключ. Добавляется блоком в `~/.hermes/cliproxy/config.yaml` (ключ вводит владелец сам):

    claude-api-key:
      - api-key: "<ключ>"
        base-url: "https://api.<провайдер>/coding"
        models:
          - name: "<модель у провайдера>"
            alias: "<короткое имя>"

Список моделей провайдера узнать запросом `GET <base-url>/v1/models` с этим ключом. Потом перезапуск
шлюза и снова `tools/features.sh --id <id> --on pool`.

## Безопасность
- Сборка только одобренной версии (`gateway/cliproxy-approved.txt`: тег + точный коммит). Коммит не совпал
  или в коде появились незнакомые сетевые адреса - установка останавливается.
- Ключи шлюза генерируются на сервере и не выводятся на экран. Входы в подписки - в `cliproxy/auths/`
  (права 700), в бэкап GitHub не попадают.
- Сервер без прямого интернета (защищённая установка) - pool-install.sh сам прописывает шлюзу фильтр.

## Обновление шлюза
Сторож шлюза раз в неделю сообщает, если в наборе одобрена новая версия. Тогда:
`cd ~/hermes-kit && git pull && tools/pool-update.sh`.
